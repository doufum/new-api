# RightToken User Console Branding Design

## 背景

本次需求是在 `web/user-console` 中做实例品牌定制，将面向终端用户可见的默认品牌从 `New API` 调整为 `RightToken`。

本次仅处理前端展示层，不修改后端接口、数据库字段或项目归属信息。

## 目标

- 将 `user-console` 的默认展示品牌切换为 `RightToken`
- 同步替换默认 `logo` 与 `favicon`
- 覆盖公开页面与认证页面中的主要品牌展示入口
- 保持项目受保护归属信息不变

## 非目标

- 不修改 `new-api / QuantumNous` 项目名称、仓库地址、许可证、归属信息
- 不修改后端 `/api/status` 返回结构
- 不修改管理端或其他前端应用
- 不处理正式品牌素材接入，本次先使用前端占位品牌资产

## 方案

采用“前端写死 + 占位品牌资产”的最小品牌化方案。

实现原则：

- 默认品牌名统一改为 `RightToken`
- 默认品牌图统一改为 `RightToken` 占位图标
- 只改默认回退值和静态展示入口
- 不移除后端可配置能力，只是不依赖它完成本次需求

## 影响范围

### 1. 默认品牌配置

修改 `user-console` 中默认品牌常量：

- 默认系统名
- 默认 logo 路径

确保在后端未下发 `system_name/logo` 时，前端仍显示 `RightToken`

### 2. 浏览器标题与图标

调整以下行为：

- 页面初始化时的默认标题展示为 `RightToken`
- 默认 favicon 指向新的占位品牌图标

### 3. 品牌展示入口

覆盖以下位置的默认品牌展示：

- 首页品牌区域
- 认证页品牌头
- 设置初始化页品牌头
- 页脚中的实例品牌名
- 其他使用默认系统名回退值的展示点

### 4. 受保护归属信息

以下内容必须保留原样：

- 项目仓库链接
- `new-api / QuantumNous` 归属信息
- 关于页中的项目级说明与许可证入口

## 占位素材策略

由于当前没有正式素材，本次使用占位品牌资产：

- 新增 `RightToken` 默认 logo 资源
- 新增 `RightToken` 默认 favicon 资源
- 风格保持简洁，便于后续直接替换为正式素材

后续如用户提供正式素材，只需替换静态资源及必要引用路径。

## 测试策略

- 为默认品牌常量增加或更新单测
- 验证在未配置后端品牌字段时，页面品牌名回退为 `RightToken`
- 验证构建通过

## 风险与约束

- 若部分页面直接写死 `New API` 字样而非走默认配置，需要补充替换
- 若某些展示点优先读取后端配置，则在真实部署中仍可能被服务端品牌覆盖
- 项目归属信息不能按实例品牌一并替换，这是明确约束，不属于缺陷
