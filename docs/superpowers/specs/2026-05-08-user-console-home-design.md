# `web/user-console` 首页重构设计

日期：`2026-05-08`

## 1. 背景与目标

`web/user-console` 当前首页更接近“用户控制台入口页”，主叙事集中在模型测试、密钥管理和操练场访问。该表达方式适合已进入系统的用户，但不适合作为面向新访客的托管服务型首页。

本次重构参考 `https://uniapi.ai/` 首页的信息组织方式，但不照搬其营销语气或页面结构。目标是在 `new-api` 的 `user-console` 中，将首页重构为更明确的“托管服务站”首页：

- 首先传达“更低成本接入主流 AI 模型”的业务价值；
- 其次建立“服务、支持、可落地”的可信感；
- 再过渡到“统一网关、稳定性、权限、计费与治理”的能力说明；
- 最终把主转化动作收敛到 `注册 / 进入控制台`，把次级转化动作收敛到 `查看模型 / 定价`。

本次设计默认服务对象是混合受众，但优先顺序明确为：

1. 成本、服务、支持、可落地
2. 统一网关、稳定性、权限、计费与治理

## 2. 设计定位

首页品牌表达采用“官方托管服务站”定位，弱化开源、自部署、社区属性在首页主叙事中的占比。

表达原则如下：

- 不把首页做成开源项目介绍页；
- 不将自部署能力作为首屏核心卖点；
- 不依赖具体数字强化说服力；
- 不使用无法明确支撑的“最低价”“绝对稳定”“行业领先”等承诺性表述；
- 更偏企业可信，但中下段允许适度提高转化密度。

整体视觉与信息风格采用“平衡漏斗”方向：

- 首屏先建立企业可信与成本优势；
- 中段解释为什么这种服务比多家直连更省事；
- 后段补足治理能力；
- 结尾以统一 CTA 收口。

## 3. 用户与转化

### 3.1 目标用户

首页面向混合受众：

- 业务与采购相关角色：更关注成本、服务、支持、是否容易落地；
- 技术负责人：更关注统一接入、稳定性、权限、计费与治理；
- 开发者：关注是否能快速上手、查看模型与价格、进入控制台。

### 3.2 转化路径

主转化动作：

- 未登录用户：`注册`
- 已登录用户：`进入控制台`

副转化动作：

- `查看模型 / 定价`，承接到 `/pricing`

不作为首页主 CTA 的内容：

- 文档
- 社区
- 支持
- 联系销售

这些内容可以存在于导航或页脚，但不应分散首页核心转化链路。

## 4. 信息架构

首页采用以下顺序：

1. `Hero`
2. `Trust Bar`
3. `Value Sections`
4. `Governance Section`
5. `Closing CTA`

该顺序的核心逻辑是：

1. 先讲用户直接感知的价值；
2. 再快速建立可信感；
3. 然后解释为何这套服务比自行接入多家模型更省事；
4. 再补足技术与管理能力；
5. 最后把用户带回统一 CTA。

## 5. 模块设计

### 5.1 Hero

Hero 是整页最重要的价值表达区域，应承担以下任务：

- 明确产品是面向 AI 模型接入的托管服务；
- 传达“低成本接入主流 AI 模型，快速落地到业务”的核心价值；
- 给出主 CTA 和副 CTA；
- 用右侧信息面板承接可信信号。

#### 内容结构

左侧：

- 小型定位标签，例如“AI Gateway”或更偏服务化的表述；
- 一句强主标题，聚焦低成本接入与业务落地；
- 一段辅助说明，补充服务、支持、接入便利性；
- 两个按钮：
  - 主按钮：`注册 / 进入控制台`
  - 副按钮：`查看模型 / 定价`
- 三个简短价值点：
  - 成本更可控
  - 服务更省心
  - 接入更直接

右侧：

- 不使用后台真实截图；
- 改为“运营控制面板感”的信息面板；
- 展示的应是可信信号而不是细碎功能：
  - 调用成本状态
  - 模型接入覆盖
  - 可用性 / 接入状态

右侧面板的作用不是展示功能，而是降低纯营销页的空泛感，让页面更像一项真实可运营的服务。

### 5.2 Trust Bar

`Trust Bar` 位于 Hero 之后，是一层短信息区域，只承担建立安全感的职责，不展开复杂叙述。

建议承载的信息类型：

- 兼容主流模型接口
- 模型与价格透明可查
- 提供接入文档与使用支持
- 面向真实业务落地场景

设计要求：

- 信息密度短平快；
- 不写复杂技术细节；
- 不写无法验证的数字承诺；
- 更像可信摘要，而不是第二个卖点区。

### 5.3 Value Sections

中段先解释“为什么这种服务比自己分别接各家模型更省事”，从业务与落地便利性切入，而不是先讲架构内部能力。

建议拆成 3 个价值卡片或 3 个并列模块：

1. 统一接入多模型
2. 成本更可控
3. 更快落地

每个模块的职责如下：

#### 统一接入多模型

- 说明多模型调用不必重复适配；
- 强调减少多家接口接入与切换的摩擦；
- 聚焦“统一入口”带来的业务简化。

#### 成本更可控

- 说明用户可以更方便地查阅模型与价格信息；
- 强调更清晰的模型选择与调用成本判断；
- 用“可控、可查、可管理”替代夸张价格话术。

#### 更快落地

- 强调从注册、测试到正式接入的链路更短；
- 说明其适合真实业务接入，而不是停留在演示层；
- 传达“少做重复接线工作”的收益。

此部分不要演变成后台功能清单，也不要把治理能力提前讲太深。

### 5.4 Governance Section

治理能力模块用于承接技术负责人关注点，将叙事从“能买能用”推进到“可以持续运营和管理”。

该模块应覆盖以下主题：

- 统一网关
- 稳定性与调用治理
- 权限与团队协作
- 计费与使用管理

表达方式要求：

- 用业务可理解的话讲能力；
- 不写成系统设置手册；
- 不罗列过多底层配置项；
- 强调它对日常运营、团队协作、使用控制的意义。

这一段的关键不是“展示功能有多少”，而是说明该服务不只是一个转发入口，而是带有实际治理能力的运营载体。

### 5.5 Closing CTA

底部 CTA 用于收口全页转化，不引入新目标。

建议结构：

- 一句总结性收口文案；
- 主按钮继续推动 `注册 / 进入控制台`；
- 副按钮继续承接 `查看模型 / 定价`。

设计目标：

- 保持整页 CTA 语义一致；
- 让犹豫用户有“先去看模型和价格”的自然出口；
- 避免在结尾再引导到文档、社区、FAQ、支持等分散路径。

## 6. 文案策略

首页文案采用以下原则：

- 先讲用户收益，不先讲系统组成；
- 用能力类型表达，不依赖具体数字；
- 优先使用“可控、可查、可落地、可管理、统一接入”这类可成立表述；
- 保持企业可信，但避免机械和空洞；
- 不把开源、自部署、社区生态写成首页主叙事。

允许出现的表达类型：

- 更低成本地接入主流 AI 模型
- 更快完成业务接入
- 更清晰地查看模型与价格
- 更方便统一管理接入与使用

避免出现的表达类型：

- 全网最低价
- 绝对稳定
- 行业第一
- 企业级领先
- 无条件兼容一切场景

## 7. 交互与视觉约束

### 7.1 总体风格

风格为折中方案：

- 首屏偏企业可信；
- 中下段适度提高转化密度；
- 不做过度炫技或 AI 风格化设计；
- 避免首页视觉语言过于“开源项目文档站”。

### 7.2 动效

动效应保持克制，只保留有意义的过渡：

- 区块入场；
- 卡片悬停；
- 按钮悬停；
- 轻量的层次移动或阴影变化。

不引入以下内容：

- 复杂轮播
- 高成本粒子动画
- 与信息理解无关的炫技特效

### 7.3 响应式

移动端要求：

- 首屏文案优先，CTA 可快速触达；
- 右侧信息面板自然下折；
- 各模块不出现横向滚动；
- 信息卡片保持足够点击面积和间距；
- 不依赖 hover 才能理解内容。

## 8. 实现边界

本次重构只针对首页，不扩散到整个公共站点体系。

应保留的整体结构：

- `PublicLayout`
- 公共头部
- 公共页脚

允许调整的首页结构：

- 当前 `Hero / Features / HowItWorks / CTA`
- 重组为 `Hero / Trust Bar / Value Sections / Governance / CTA`

实现方式应尽量在 `web/user-console/src/features/home/` 范围内完成，不扩大影响面。

可以复用现有 section 文件，也可以按职责轻量调整，但不应把本次工作演变为整套公共组件体系重构。

## 9. i18n 约束

首页新增文案必须接入当前国际化体系。

要求如下：

- 新首页文案统一使用 `t(...)`
- 同步补全：
  - `en`
  - `zh`
  - `fr`
  - `ja`
  - `ru`
  - `vi`
- 若存在常量驱动文案，需同步补充到 `web/user-console/src/i18n/static-keys.ts`

不允许只更新中英文后结束工作。

## 10. 测试与验证

至少需要验证以下内容：

### 10.1 单元/组件层

更新首页测试，确认：

- 新主标题渲染正确；
- 主 CTA 渲染正确；
- 副 CTA 渲染正确；
- 核心首页内容与新定位一致。

### 10.2 构建与运行层

完成实现后至少执行：

- `bun run test:run`
- 必要的类型或构建检查

### 10.3 人工验收层

需要人工确认：

- 首页看起来像托管服务站，而不是控制台欢迎页；
- 首屏先讲成本、服务、支持、可落地；
- 中下段自然过渡到统一网关与治理能力；
- CTA 路径保持统一；
- 移动端首屏阅读和点击清晰。

## 11. 非目标

以下内容不在本次设计范围内：

- 改造整个公共导航系统
- 改造页脚信息架构
- 新增文档页、支持页或销售页
- 重构 `pricing` 页面
- 将首页改回以开源、自部署为主的产品介绍页
- 引入大规模视觉品牌升级或设计系统重做

## 12. 结论

本次首页重构采用“托管服务站 + 平衡漏斗”的设计方向。

最终叙事顺序确定为：

1. 更低成本接入主流 AI 模型
2. 服务、支持、可落地
3. 为什么比多家直连更省事
4. 统一网关、稳定性、权限、计费与治理
5. 注册或查看模型定价

这套设计既避免当前首页过于“控制台入口化”，也避免直接复制参考站点的纯营销表达，能够在现有 `user-console` 代码结构内以较小范围完成重构。
