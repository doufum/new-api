# Claude Code

这页文档只说明“如何把 Claude Code 指到当前网站”，不保证第三方工具本身所有版本都使用完全相同的环境变量名。最稳妥的做法始终是：以你当前工具版本的官方说明为准，再把网关地址和 API 密钥替换进去。

## 什么时候适合先看这页

如果你已经确认下面两件事成立，就可以开始接 Claude Code：

1. 你能在 [游乐场](/playground) 正常发起请求。
2. 你已经有一个可用的 API 密钥。

如果这两件事还没确认，先回到 [新手入门](/workspace/docs/getting-started/intro)。

## 最小环境变量示例

Claude 类工具通常直接指向网关根地址，而不是把基地址写成带 `/v1` 的形式。

```bash
export ANTHROPIC_BASE_URL="<rightmaas_base_url>"
export ANTHROPIC_API_KEY="sk-your-api-key"
```

把 `<rightmaas_base_url>` 换成你的实际网关根地址即可。

## 连接前建议先做一次验证

先发一个最小请求，确认：

- API 密钥可用
- 网关可达
- 账号确实有 Claude 类模型权限

如果你当前账号并没有开放 Claude 模型，Claude Code 这类工具即使配置正确，也仍然可能请求失败。

## 使用“CC 切换”快速导入

如果你在 [API 密钥](/workspace/keys) 列表的操作菜单里看到了“CC 切换”，可以直接把当前站点地址、API 密钥和模型带到外部应用。

这个方式适合不想手动抄环境变量的情况。

## 模型选择建议

如果 Claude Code 支持指定模型，建议优先：

1. 先选一个你在 [游乐场](/playground) 已验证通过的 Claude 模型。
2. 如果你给 API 密钥设置了“模型限制”，确认该模型在允许列表里。
3. 如果你走 `auto` 分组，必要时在日志里检查是否有跨组回退。

## 常见失败原因

### 配置了环境变量，但工具还是报认证错误

优先检查：

- API 密钥是否真的带了 `sk-` 前缀
- 是否使用了真实 API 密钥，而不是表格展示的脱敏值
- 账号是否已过期、禁用或额度不足

### 工具能连上，但具体请求失败

优先检查：

- 当前账号是否有 Claude 模型权限
- API 密钥是否限制了可用模型
- 当前站点是否真的配置了 Claude 上游

## 出问题时怎么排查

最短路径：

1. 到 [游乐场](/playground) 用同一个账号测试 Claude 模型。
2. 到 [请求日志](/workspace/logs) 查这次请求是否落日志。
3. 按 `model`、`group`、`requestId` 看失败详情。

如果你的 Claude Code 版本配置方式不同，以你正在使用的版本说明为准，再把站点地址和 API 密钥替换进去即可。
