# 常见问题

## 我应该先看哪个页面确认是否能正常使用？

建议按这个顺序：

1. [API 密钥](/workspace/keys) 创建一个可用密钥。
2. [游乐场](/playground) 直接发送一条测试消息。
3. [请求日志](/workspace/logs) 查看是否真的有请求记录。
4. [钱包](/account/wallet) 确认余额或订阅状态。

这样排查效率通常最高。

## 游乐场能用，但我自己的代码调用失败，先查什么？

优先对比下面四项是否和游乐场 / 文档示例一致：

- 基础地址
- `Authorization: Bearer ...`
- `model`
- 请求体 JSON 结构

如果还是不通，直接去 [请求日志](/workspace/logs) 按 `requestId` 或时间范围查具体错误。

## 为什么会返回 401？

最常见原因：

- API 密钥写错了
- 没有带 `Bearer` 前缀
- 使用了脱敏后的展示值，而不是真实 Key
- Key 已过期、已禁用或已删除

## 为什么返回 403，但 Key 明明是对的？

这种情况更像“认证成功但没有权限”，常见原因包括：

- “模型限制”限制了当前模型
- 当前账号或 API 密钥没有访问该模型的权限
- 分组没有可用通道

## 为什么有余额还会调用失败？

余额足够不代表所有限制都放开了。还要检查：

- 某个 API 密钥是否有独立额度限制
- API 密钥是否已经过期
- 当前分组是否可用
- 是否触发了速率限制
- 是否命中了订阅或其他计费策略

## 什么时候应该使用 `auto` 分组？

当你不想在业务侧手工维护具体分组时，优先用 `auto`。如果页面里同时出现“跨分组重试”，建议保持开启，这通常是默认最稳妥的配置。

## 为什么建议给不同系统分不同 Key？

因为这样更容易：

- 按来源看请求日志
- 做额度隔离
- 吊销单个调用方
- 分析某个系统的真实消耗

比如 Web 服务、定时任务、CLI 工具，建议至少拆成三个不同 API 密钥。

## 哪里可以看某次请求到底用了哪个模型？

去 [请求日志](/workspace/logs) 看“通用日志”。如果日志里开启了更完整的明细，你通常还能看到：

- 请求模型
- 上游实际模型
- 分组
- Token 消耗
- 错误原因
- 重试链路或其他补充信息

## 如何快速验证一个新 API 密钥是不是可用？

最短方式有两种：

1. 进 [游乐场](/playground) 用这个账号直接发一条消息。
2. 调用 `<rightmaas_base_url>/v1/models` 或 `<rightmaas_base_url>/v1/chat/completions` 做最小请求。

如果这两种都失败，再回到 [API 密钥](/workspace/keys) 检查这个 API 密钥的：

- 过期时间
- 额度
- 模型限制
- 分组设置

## 钱包里为什么看不到某种支付方式？

因为钱包页是按系统配置动态展示的。某个实例是否显示 Stripe、Creem、Waffo 或其他支付方式，取决于后端是否已经启用并配置完成。

## 我想进一步丰富文档，应该补什么资料？

如果你希望文档继续往“更像正式产品文档”推进，最值得补的参考资料通常是：

- 你的线上访问域名和正式 `<rightmaas_base_url>`
- 你实际开放给用户的模型清单
- 你启用的支付方式和最低充值规则
- 你希望重点支持的外部工具接入说明

如果你提供这些信息，我可以继续把工具接入文档和计费文档写得更具体。
