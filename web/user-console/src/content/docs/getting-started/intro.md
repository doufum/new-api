# 新手入门

这份说明按网站当前可用的实际操作流程整理，目标是让你在几分钟内完成从登录、创建密钥到发送第一条请求的完整闭环。

## 你会用到哪些页面

| 页面 | 路径 | 用途 |
| --- | --- | --- |
| API 密钥 | `/workspace/keys` | 创建和管理调用密钥 |
| 文档 | `/workspace/docs` | 查看接入说明、工具示例、计费文档 |
| 游乐场 | `/playground` | 直接在网页里选模型并测试对话 |
| 使用日志 | `/workspace/logs` | 查看请求记录、Token、分组、错误明细 |
| 钱包 | `/account/wallet` | 充值、兑换充值码、查看账单和订阅 |

## 第一步：登录并确认账号状态

登录后，建议先确认两件事：

1. 你的账号是否已经有可用余额或订阅额度。
2. 你的账号是否能看到可用模型和可用分组。

如果你刚注册完成，通常可以先到 [钱包](/account/wallet) 看余额，再到 [游乐场](/playground) 或 [API 密钥](/workspace/keys) 看模型列表是否已经返回正常数据。

> 如果页面里没有模型或分组，通常不是前端问题，而是当前账号没有对应权限，或者管理员还没有为你分配默认分组。

## 第二步：创建第一个 API 密钥

进入 [API 密钥](/workspace/keys)，点击“创建 API 密钥”。

第一次创建时，通常只需要关注这几个画面字段：

- `名称`：给密钥起一个便于识别的名字。
- `分组`：选择默认分组；如果页面默认是 `auto`，通常可以先保持不变。
- `过期时间`：决定这个密钥什么时候失效；测试用密钥建议设置过期时间。
- `无限配额`：开启后，这个密钥不受单独额度限制。
- `额度`：关闭“无限配额”后，可以单独给这个密钥设置额度。
- `模型限制`：只允许这个密钥访问指定模型。

如果你只是先验证链路是否打通，最简单的做法是：

1. 填好“名称”。
2. “分组”先用当前默认值，或者直接选 `auto`。
3. “过期时间”按需要设置；只是临时测试的话，建议给一个较短期限。
4. 如果不想让这个密钥无限使用，就关闭“无限配额”，再填一个较小的“额度”。
5. 如果你只打算测试某几个模型，再补充“模型限制”。

## 第三步：用游乐场先跑通一次

在 [游乐场](/playground) 页面里，前端会自动拉取当前账号可用的：

- 模型列表
- 分组列表

你可以直接：

1. 选择一个模型。
2. 选择一个分组，或保持 `auto`。
3. 输入一条简单消息，比如“请返回 ok”。
4. 观察是否正常返回内容。

游乐场还支持这些调试动作：

- 停止生成
- 编辑上一条用户消息后重新发送
- 对助手回复执行重新生成

如果游乐场都跑不通，不要急着先改 SDK 代码，先看 [请求日志](/workspace/logs) 的返回详情，更容易定位问题。

## 第四步：发送第一条 OpenAI 兼容请求

前端验证通过后，再用你自己的脚本或命令行发真实 API 请求。

```bash
curl "<rightmaas_base_url>/v1/chat/completions" \
  -H "Authorization: Bearer sk-your-api-key" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "gpt-4o-mini",
    "messages": [
      { "role": "user", "content": "Reply with OK only." }
    ]
  }'
```

把 `<rightmaas_base_url>` 替换成你的实际网关地址即可。这里的占位符只表示站点根地址，不要在基地址本身再额外写成带 `/v1` 的形式。

## 第五步：到日志里确认请求是否真的命中

进入 [使用日志](/workspace/logs) 后，优先看“通用日志”。

这里通常会帮助你确认：

- 实际请求用了哪个模型
- 命中了哪个分组
- 消耗了多少输入 / 输出 Token
- 是否发生模型映射
- 是否返回了错误
- `requestId` 是什么

如果你在排查问题，最有用的几个筛选条件通常是：

- `model`
- `group`
- `token`
- `requestId`
- 时间范围

## 第六步：根据需要补充余额或兑换码

如果请求因为余额不足失败，进入 [钱包](/account/wallet)：

- 直接充值
- 使用充值码兑换
- 查看历史账单
- 查看是否有订阅计划可用

不同部署可能会启用不同支付方式，例如在线支付、Stripe、Creem、Waffo 或 Waffo Pancake。页面只会展示当前系统已经开启的方式。

## 常见的最短排查路径

当你第一次接入失败时，建议按下面顺序查：

1. API 密钥是否创建成功，且没有过期。
2. 该 Key 是否被限制了模型，或额度已经耗尽。
3. 游乐场是否能用同一个账号正常返回。
4. [请求日志](/workspace/logs) 中是否能看到对应请求。
5. 如果能看到日志，再检查具体错误详情和 `requestId`。
