# API 密钥说明

API 密钥是调用网关接口的凭证。你可以在 [API 密钥](/workspace/keys) 页面创建、更新、禁用、删除和复制它们。

## 创建入口

在 [API 密钥](/workspace/keys) 页面点击“创建 API 密钥”后，会打开一个带分区的抽屉表单。对大多数用户来说，只需要理解少数几个常用字段。

## 基本信息

| 字段 | 说明 | 建议 |
| --- | --- | --- |
| `名称` | 备注名称 | 用用途或环境命名，例如“后端测试”“团队联调” |
| `分组` | 默认分组 | 不确定时优先使用 `auto` |
| `跨分组重试` | 当前分组失败后继续尝试下一分组 | 只有在分组为 `auto` 时才会出现 |
| `过期时间` | 密钥失效时间 | 测试密钥建议设置过期时间 |
| `数量` | 一次创建几个密钥 | 需要发给多个客户端时再用 |

如果你不清楚该选哪个分组，通常可以先用 `auto`。当页面同时出现“跨分组重试”时，建议保持开启，这样在当前分组不可用时会继续尝试下一个可用分组。

## 额度设置

| 字段 | 说明 |
| --- | --- |
| `无限配额` | 开启后，这个密钥不受单独额度限制 |
| `额度` | 关闭“无限配额”后，可以给这个密钥单独设置额度 |

几个实际建议：

- 给服务端正式环境使用的 API 密钥，通常建议设置明确额度。
- 给本地联调或短期测试使用的 API 密钥，建议设置较小额度并加过期时间。
- 只有在你确认调用方完全可信时，才建议开启“无限额度”。

## 高级设置

高级区域里，普通用户最常用的是“模型限制”。

如果你只想让某个密钥调用少数几个模型，就在“模型限制”里直接勾选它们。留空则表示不额外限制模型范围。

## 批量创建

当你需要同时发给多个客户端时，可以使用“数量”一次创建多个密钥。系统会保留第一条名称，并为其余密钥自动补充后缀，适合：

- 一次给多个测试环境分发密钥
- 给多个客户端实例预生成凭证
- 做短期压测或临时联调

## 复制与发放

API 密钥创建后，表格中支持复制真实密钥。发放时建议遵循以下原则：

1. 不要把真实 Key 提交到仓库。
2. 不要直接写死在浏览器前端源码里。
3. 生产环境优先放到服务端环境变量或密钥管理系统。

## 一个更稳妥的实践模板

比较稳妥的做法通常是：

- 默认走自动分组，容错更高
- 有过期时间，不容易遗留长期有效测试凭证
- 有额度上限，不会无限消耗
- 按需加上“模型限制”，不容易被误用于高价模型

## 什么时候应该新建一个 Key

建议在这些场景拆分不同 API 密钥：

- 不同环境：开发、测试、生产
- 不同业务：聊天、嵌入、图像
- 不同调用方：Web 服务、Worker、CLI 工具
- 不同责任边界：个人调试、共享服务、第三方集成

这样在 [请求日志](/workspace/logs) 里排查问题时，能更快按 token 名称反查来源。

## 常见问题

### 为什么请求返回 401

优先检查：

- Header 是否写成 `Authorization: Bearer <key>`
- Key 是否被删除或禁用
- Key 是否已经过期

### 为什么创建成功后还是调用失败

优先检查：

- “模型限制”是否拦住了当前模型
- 额度是否耗尽
- 所选 `group` 是否没有可用通道
- 在 `auto` 模式下是否需要开启“跨分组重试”

### 为什么建议给不同系统分不同 Key

因为在日志里可以更清楚地区分来源，也更容易：

- 做额度隔离
- 快速吊销单个调用方
- 单独分析某个系统的消耗
